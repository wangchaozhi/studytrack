# 学迹 StudyTrack 产品原型

> 版本：V1.0 MVP
> 产品形态：响应式 Web 应用
> 技术实现：Go REST API + React + TypeScript + PostgreSQL

## 1. 产品概述

学迹 StudyTrack 是一套面向长期考试与阶段性复习的个人学习追踪系统，覆盖以下三种主要场景：

- 学位课程复习
- 考研复习
- 雅思备考

产品围绕完整学习闭环设计：

```text
学习目标 → 阶段计划 → 每日任务 → 专注记录 → 测试成绩 → 学习复盘 → 调整计划
```

系统不只记录“学了多久”，还同时追踪任务完成率、知识点掌握程度、练习与模考成绩、薄弱项和复习节奏。

---

## 2. 产品目标

### 2.1 核心目标

1. 让用户每天清楚知道当前最重要的学习任务。
2. 让长期目标可以被拆解为阶段、科目、知识点和每日任务。
3. 同时衡量学习投入与学习效果。
4. 通过数据分析和每周复盘帮助用户及时调整计划。
5. 使用统一模型支持学位复习、考研和雅思，不重复建设三套系统。

### 2.2 MVP 成功标准

用户可以完成以下闭环：

1. 注册并登录。
2. 创建一个学习目标。
3. 系统自动生成默认阶段与科目。
4. 新建并完成学习任务。
5. 使用专注计时记录实际学习过程。
6. 更新知识点掌握程度。
7. 录入一次练习或模考成绩。
8. 在首页和分析页看到学习结果。
9. 完成一份每周复盘。

---

## 3. 用户角色

MVP 只包含一种角色：个人学习者。

典型用户包括：

| 用户类型 | 主要需求 |
|---|---|
| 大学生 | 管理课程章节、期末考试与目标成绩 |
| 考研学生 | 管理院校目标、科目、复习轮次、真题与模考 |
| 雅思考生 | 管理听说读写、词汇、单项成绩与考试日期 |

后续版本可以增加教师、辅导员、班级管理员和机构管理员等角色。

## 6. 核心用户流程

### 6.1 首次使用流程

```mermaid
flowchart LR
    A[注册/登录] --> B[选择目标类型]
    B --> C[填写考试信息]
    C --> D[自动生成阶段和科目]
    D --> E[创建首个任务]
    E --> F[开始专注]
    F --> G[提交学习记录]
    G --> H[首页查看结果]
```

### 6.2 日常学习流程

```text
进入首页
→ 查看今日任务与逾期任务
→ 选择任务并开始专注
→ 完成后填写专注度和掌握度
→ 必要时更新关联知识点
→ 查看今日完成率和学习时长
```

### 6.3 周期复盘流程

```text
查看本周学习数据
→ 对比计划时间与实际时间
→ 识别薄弱科目和知识点
→ 填写问题与总结
→ 设置下周重点
→ 调整后续任务
```

## 7.7 专注学习

### 页面目标

用尽量少的干扰记录一次真实学习过程。

### 线框图

```text
┌──────────────────────────────────────┐
│ 高等数学：极限与连续                 │
│                                      │
│               42:18                  │
│                                      │
│          [暂停]   [完成学习]         │
│                                      │
│ 今日累计：2小时35分钟                │
│ 当前任务预计：60分钟                 │
│                                      │
│ 临时笔记                             │
│ [_________________________________]  │
└──────────────────────────────────────┘
```

### 开始专注

用户选择：

- 学习目标
- 学习任务，可选
- 学习科目，可选

系统创建一条进行中的学习记录，并记录开始时间。

### 完成专注

用户填写：

| 字段 | 范围 |
|---|---|
| 实际时长 | 自动计算，允许修正 |
| 专注程度 | 1—5 |
| 掌握程度 | 1—5 |
| 学习笔记 | 可选 |

结束后：

- 更新学习记录。
- 将学习时长计入今日、本周和科目统计。
- 关联任务时，累计任务实际时长。
- 用户可继续在任务页完成任务状态。

## 7.8 知识点

### 页面目标

维护科目知识结构，识别薄弱项，并记录复习状态。

### 知识点树示例

```text
高等数学
├── 函数与极限
│   ├── 数列极限
│   ├── 函数极限
│   └── 无穷小
├── 导数与微分
└── 积分
```

### 知识点字段

| 字段 | 说明 |
|---|---|
| 名称 | 必填 |
| 所属科目 | 必填 |
| 父知识点 | 支持树形结构，可选 |
| 重要程度 | 普通、重点、核心 |
| 掌握度 | 0—100 |
| 复习状态 | 未学习、学习中、已掌握、需复习 |
| 下次复习时间 | 可选 |
| 复习次数 | 自动累计 |
| 错题数 | 手动或后续自动关联 |

### 掌握度建议

后续智能版本可使用以下加权逻辑：

```text
掌握度 =
主观掌握评分 × 20%
+ 练习正确率 × 35%
+ 模考表现 × 30%
+ 近期复习情况 × 15%
```

MVP 允许直接更新掌握度和复习状态，避免过早引入复杂算法。

- 科目进度
- 成绩趋势

- 薄弱知识点

#### 学习质量

- 平均专注评分
- 主观掌握评分
- 高效学习日期和科目

## 13. 非功能需求

### 安全

- 密码必须以 bcrypt 哈希保存。
- 除注册、登录、健康检查外，业务接口需要 JWT。
- 用户只能访问自己的目标和关联数据。
- 生产环境必须使用 HTTPS 和高强度 JWT 密钥。

### 性能

- 首页聚合接口应一次返回主要数据，减少前端串行请求。
- 列表接口应支持日期或目标筛选。
- 数据量增长后为用户 ID、目标 ID、计划日期和考试日期增加索引。

### 可维护性

- 前后端类型和枚举保持一致。
- 业务数据按用户隔离。
- 数据库迁移保持幂等或使用版本化迁移。
- 三类学习目标共享基础模型，通过模板和扩展设置体现差异。

## 15. 验收用例

### 用例 1：创建考研目标

1. 用户注册并登录。
2. 选择“考研”。
3. 填写名称、日期、目标分数和院校信息。
4. 提交后目标创建成功。
5. 系统自动生成基础轮、强化轮、真题轮、冲刺轮。
6. 系统自动生成政治、英语、数学和专业课。

### 用例 2：完成一次专注学习

1. 用户创建“高数极限练习”任务。
2. 在专注页选择该任务并开始。
3. 完成后提交时长、专注评分和掌握评分。
4. 首页今日学习时长增加。
5. 任务实际时长更新。
6. 统计页出现当天学习数据。

### 用例 3：维护薄弱知识点

1. 用户在数学科目创建“概率论”知识点。
2. 设置掌握度为 42、状态为“需复习”。
3. 首页或分析页显示该薄弱知识点。
4. 用户完成复习后更新掌握度和下次复习时间。

### 用例 4：录入雅思成绩

1. 用户选择雅思目标。
2. 创建类型为“雅思”的成绩记录。
3. 填写总分和听说读写详细分数。
4. 记录出现在成绩列表。
5. 分析页成绩趋势同步更新。

### 用例 5：提交周复盘

1. 用户选择目标和周开始日期。
2. 填写计划时长、实际时长、总结、问题和下周重点。
3. 保存后出现在历史复盘列表。
4. 用户可根据复盘内容调整下一周任务。
